### 0.3 本轮审查确定的问题

**R01 — 分数网格插值归因过度。** V140把四例offset超过1%的原因直接写成“56 nm复场样本的双线性插值误差”。其判断有线索支持：M02位移正好整数网格、offset重放优良，其他四例含分数56 nm网格；但V140**未在同一偏移条件下直接比较实际MAT保存的复散射场**`Esca_at_offset`与从同一source宽场计算`Esca_wide(x−dx,y−dy)`，更没有独立给出Er场、Icross和Isca贡献。因此“全由双线性造成”是**待验证假设**，不是已经排除其他因素的科学结论。V141最优先需要完成场级误差隔离。

**R02 — 有旧失败文件，但发布称通过。** `results/v140/validation/canonical_oracle_error.json`保存`Frozen source Git blob mismatch: tools/v125_model_library.py`，而 `canonical_oracle_summary.json`和12行CSV提供之后的成功结果；发布程序 `verify_frozen_source()`为了容忍机读配置中的**41字符Git blob笔误**，允许精确40字符前缀匹配并添加日志。历史失败应保存、区分失败尝试和后续成功尝试，不得直接当作最后科学执行被阻断；但下一版冻结检查**必须使用原文件真实完整40字符Git blob**，拒绝41字符、前缀以及模糊比对；成功重放写实际run_id、源码SHA、输入SHA和命令，不允许还靠摘要解释。

**R03 — “零偏移6/6、M02整数移位成功”不等于全部空间模型已验收。** 零偏移是基准检验，M02整数移位仅检验网格对齐。分数位移能否通过，须检验场样本插值及像元积分，保留原1%门槛，不因想通过而放宽。

**R04 — V140 F2子模块计费及归档需改为事件先预留。** V140 `v140_fourway.py`在计算F2后才向SQLite写总额，重跑会重复插入；`v140_canonical_oracle.py`虽正常oracle不调用F2，亦保留了早期失败文件。新执行应所有F2、render和其他重计算从**同一个原子台账先预留**，失败重试也计费，真正续算由完整源+图像+模型+规则指纹确认；旧V137超额需永久保留，不可由V141预算替代。

### S1 — 使用同一原solve的default、wide、at_offset复场做场级误差分离（本轮最重要实际运行阶段）


从一个M的三份实际原render读取复参考场、复散射场、`rmeta(dx,dy,q,focus)`、fine axis、17×17原 `Itotal,Iref,C`；原宽场为25×25对应125×125采样，直接offset场为17×17对应85×85采样，均为q5。**只用单一预定义转换，不能因为哪种方向误差最小而在每颗上搜索8种翻转。**

对于每个M，目标 `direct` 为源偏移render在**原85×85样点上**的`Eref_direct/Esca_direct`；预测`bilinear`是冻结中心宽场`Esca_wide(x−dx,y−dy)`、`Eref_wide(x,y)`。先在复数组上计算：

- `dEr = Er_wide_at_camera − Er_direct`，`dEs = Es_wide_shifted − Es_direct`，保存复数数组、绝对L2、分别以源场L2为分母的相对L2和最大复数模。**近零范数不可加人为epsilon后把结果写成相对误差，通过标准只看可定义的量。**
- `C_exact_from_direct_fields`从**direct真实Er/Es**平方总强度、5×5积分得到；必须与该MAT文件`contrast`在已冻结轴下相符。若不符先修导入，不进入其余误差归因。
- `C_mixed_direct_Er_interp_Es` 使用真实直接参考场+宽场插值得到的散射场；对比直接C，隔离空间插值。
- `C_full_bilinear`使用宽场参考场+宽场插值散射场，对比直接C，进一步隔离参考场/坐标相关误差。
- 单独保存干涉项`Icross=2Re(conj(Er)·Es)`与`Isca=|Es|²`，比较偏差及其像元分布，避免只看`C`丢失幅相信息。

### S3 — 严格拆分`空间插值误差`与`D/h节点插值误差`

在同一个M的原direct图和原宽场oracle下计算三元配对：

1. `C_native_oracle`：真M对应同solve的宽复场 + S1或预先冻结的统一S2空间算子；没有任何D/h插值。
2. `C_F2_original`：正式冻结V133 F2，D/h三次复场插值+空间双线性；**不能改变模型含义、name或代码SHA**。
3. `C_true_direct`：MAT保存的直接偏移图，严格与合并M H5逐元素身份一致。

结果分别保存：

\[R_{space}=\|C_{oracle}-C_{direct}\|_2,\quad R_{total}=\|C_{F2}-C_{direct}\|_2,\quad R_{model-oracle}=\|C_{F2}-C_{oracle}\|_2.\]

保留**逐像元残差向量恒等式**`(F2-direct)=(F2-oracle)+(oracle-direct)`，但要强调**范数不可做代数减法**来声称“百分比贡献”。只有空间采样核固定、源血缘及物理对应证明后，才允许把`R_model-oracle`更进一步解释成主要由D/h节点插值造成；否则仍是混合模型差异。

## 3. 失败处理、禁止事项和明确返回条件

- **绝不**凭一个复杂问题就停止全部工作：S1某个MAT缺失，记录`BLOCKED_SOURCE`并继续有合法源的其他M；S2无法通过，仍可完成已有来源和软件诊断，但不能认证S4物理测径。
- **绝不**依据六M的真实粒径调整坐标、模型增益/相位、曲线阈值或兼容区间；不可把每颗不同最佳插值方法拼成正式模型。

### 实施注意（Windows源码字节与运行身份）

V137曾出现Windows签出将冻结源码从LF转换为CRLF而触发的源字节锁失败。V141遇到`SOURCE_BYTES_DIFFER_FROM_FROZEN_GIT_BLOB`时，先核对Git实际固定blob、工作树换行与编码；可在**独立只读验证环境**按`git show <fixed-sha>:<path>`恢复原字节并记录操作。禁止为了让校验成功而随意修改科学源码、缩短SHA或悄悄改变模型。若源字节不同，停止依赖该模型的科学判定并保存证据。
