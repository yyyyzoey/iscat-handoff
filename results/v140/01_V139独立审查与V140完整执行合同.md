### 0.3 关键审查R01：V139“空间平移不成立”归因**尚未被证明**

V139 `tools/oracle_wide_vs_direct.py::get_render` 通过`v139_common.complex_field`把MAT H5复数组从`[3,n,n]`转换为 `transpose(1,2,0)`，然后直接使用`query_x-dx,query_y-dy`，仅在**计算出相机C后**做 `RAW.T[::-1,:]`。但原来实际建库的 `tools/v125_model_library.py`是：

```python
# H5 compound E from MATLAB -> MATLAB array dimensions
E = np.transpose(E_h5, (2,1,0))
# _camx_flip globally normalizes source camera x on the FIELD too
E = E[::-1,:,:]
fine_x = -fine_x_raw[::-1]
fine_y = fine_y_raw
# C exported in the same frozen canonical convention
C_canonical = C_raw.T[::-1,:]
```

同时**原MATLAB adapter** `source/v126_physical_forward_adapter.m::v125_render_variant` 明确执行：

```matlab
es0 = efield(s.lens, s.far, x0-dx, y0-dy, ...);
er0 = efield(s.lens, s.reference, x0, y0, ...);
es = flip(es0,1);
er = flip(er0,1);
```

因此，**对经过翻转后才存储的复场直接使用原始dx/dy偏移，必须先证明该轴/符号定义与MATLAB源定义等价。** V139只对C应用了冻结方向，没有以同一历史读入规则证明其wide复场也进入了正确物方坐标。不能据此宣布“同solve纯空间平移在物理上失效”，更不能据此否定iSCAT测径。
